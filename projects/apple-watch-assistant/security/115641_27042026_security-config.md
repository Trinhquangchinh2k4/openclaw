# Apple Watch Assistant MVP Readiness - Security / Config Spec

## Secret handling
- do not hardcode API keys or tokens into the watchOS app
- do not hardcode secrets into frontend or dashboard files
- do not commit real secrets into repo or workspace artifacts
- use `.env`, environment variables, or a secure config store only

## Config separation
Profiles to separate:
- dev
- staging/mock
- production
- simulator
- real device/TestFlight

## Apple Watch / iPhone config model
- watchOS app should not keep long-lived secrets unless strictly necessary
- iPhone companion or backend may hold more sensitive config when appropriate
- use short-lived token or session token if needed
- keep secret exchange server-side whenever possible

## Backend auth
- API contract should require auth header or short-lived token for protected calls
- validate request shape and required fields
- apply minimal rate limit / abuse control on backend endpoints
- define timeout and retry policy for watch/iPhone client requests

## Dashboard token visibility
- dashboard only shows token usage, count, and status
- dashboard must not show raw tokens or secrets
- agent token panel should only show: input / output / total / tokenActive

## Local dev example
- `app/shared/config.example.json` must remain example-only and contain no real secrets
- optional `.env.example` may be added for local developers, also without real secrets

## Acceptance
- `security-config.md` exists
- config example remains safe and contains no real secret
- no real secret is stored in this spec
- task evidence points to the created spec and safe example config
